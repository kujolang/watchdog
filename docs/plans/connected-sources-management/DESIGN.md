# Connected Sources design and baseline

## Phase 0 evidence

The implementation started from a clean `main` worktree tracking
`origin/main`. Existing source ownership was confirmed under `src/`, with root
entrypoints generated by `scripts/sync_compat_entrypoints.js`. The baseline
auth, proxy-config visibility, tenant/project partitioning, schema migration,
frontend, documentation-link, and compatibility contracts remained the gates
for every later phase.

Existing inbound identity comes from `requests.source_app` and
`requests.provider` for proxy/legacy observations, and
`telemetry_records_v2.producer_name` plus its policy-approved source metadata
for canonical native and OTLP observations. Exporter profiles are outbound and
are deliberately excluded. Existing time/source indexes and `EXPLAIN QUERY
PLAN` coverage in the regression suite informed the read model. Unscoped
refreshes use an insert/delete-maintained derived observation summary and a
revision-aware cache; tenant/project-scoped legacy queries are capped at the
most recent 50,000 rows and 512 identities. Canonical observations are omitted
when a scope is requested because their accepted schema does not carry a
directly queryable tenant/project column.

The documented performance reference fixture contains 50,000 legacy request
rows distributed across 50 applications and four proxy profiles. The focused
benchmark warms the real loopback server, samples 100 keep-alive inventory requests, and
requires measured p95 latency at or below 25 ms.

## Decisions

- Kinds: `proxy`, `native_v2`, `otlp`, `legacy`, and operator-registered
  `observed` metadata. Export destinations are not a source kind.
- Status: a five-minute accepted-observation window yields `active`; an older
  accepted observation yields `stale`; configuration without observation is
  `pending`; local disabled configuration yields `disabled`; only persisted
  configuration/admission evidence may yield `error`.
- Merge keys: exact proxy profile, canonical producer, or legacy source-app
  identifier. Display names are never merge keys.
- Ownership: `watchdog.sources.v1` stores bounded, non-secret operator metadata
  only. Canonical and legacy telemetry schemas are unchanged.
- Mutation semantics: authenticated allowlisted changes, revision conflicts,
  atomic mode-`0600` writes, symlink refusal, retained history on delete, and
  bounded redacted audit events.
- Runtime reload: existing proxy profile selection reads configuration during
  requests, but environment ownership and all startup state cannot be proven
  safely reloadable as one transaction. Management responses therefore say
  `restart_required: true`; no activation claim is made.

The dashboard adds exactly one sequential inventory request to its existing
refresh chain. Setup templates load only when the operator opens them.
